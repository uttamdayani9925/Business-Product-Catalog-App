ABSTRACT

This project, titled "Luxe Laces: Product Catalogue & Ratings App Using Microservices and DevOps Pipeline," modernizes the B2B wholesale distribution process by transitioning from traditional physical catalogs to a high-performance, containerized digital platform. The core objective was to build a highly scalable, premium e-commerce interface backed by a robust microservices architecture. By isolating specific business domains—namely the Product Catalog Service and the Ratings Service—into independent Node.js RESTful APIs connected via an Nginx reverse proxy, the system achieves maximum stability and scalability. 

The frontend, built with React, features a premium split-layout UX, global search, and voice-assisted query execution. Advanced features include 1:1 aspect ratio image sliders mapping dual high-resolution fabric scans to individual SKUs, and immediate WhatsApp B2B lead generation. The entire stack (React, Node.js, MongoDB, Redis) is successfully containerized using Docker and Docker Compose, fulfilling modern DevOps deployment practices and establishing a foundation for CI/CD integrations.

1.0 INTRODUCTION

1.1 INTRODUCTION
The project "Luxe Laces" is a sophisticated, container-based web application tailored for B2B fashion and lace wholesale. It provides a digital catalog interface allowing users to explore different types of laces (Cotton, Polyester, GPO) with associated ratings, directly forwarding bulk inquiries via WhatsApp.

1.2 PURPOSE
The primary purpose is to eliminate physical, static catalog dependencies for wholesale buyers and replace them with a dynamic, highly available digital system. The use of microservices ensures that the catalog discovery (Product Service) operates independently of user feedback (Ratings Service), preventing bottlenecks.

1.3 PROBLEM DEFINITION
Wholesale distributors traditionally rely on static image folders or PDF catalogs, leading to outdated inventory displays, cropped images, and a lack of immediate inquiry pipelines. The existing digital solutions lacked premium aesthetics, robust search features (like voice search), and failed under heavy concurrent loads due to monolithic architectures.

1.4 SCOPE
The scope includes deploying an Nginx-proxied microservices backend (Node.js/MongoDB) and a premium React frontend. It features custom seeding scripts for bulk image linking (Riva Fashion and Gurukrupa Exports), voice search functionalities, and Dockerized deployment. Future live payment integration remains out of scope for this phase.

1.5 TECHNOLOGY AND LITERATURE REVIEW
The chosen tech stack—MERN (MongoDB, Express, React, Node.js) combined with Docker and Redis—represents the industry standard for scalable applications. Docker ensures environment consistency across development and production, while Redis provides caching layers preventing database overload.

3.2 HARDWARE AND SOFTWARE REQUIREMENTS

3.3 ASSUMPTIONS AND DEPENDENCIES
It is assumed that the client machine runs a modern web browser capable of executing the Web Speech API for voice search. The Docker daemon must be actively running to spin up the local clusters.


4.0 SYSTEM ANALYSIS

4.1 STUDY OF CURRENT SYSTEM
The previous workflow involved manually sharing specific folders ("Riva Fashion Laces", "Gurukrupa 2nd Laces") via cloud links or chat applications whenever a buyer requested designs.

4.2 WEAKNESSES OF CURRENT SYSTEM
Manual sharing is prone to human error, delays, and disjointed client experiences. Furthermore, it completely lacks tracking metrics like average ratings or product popularity.

4.3 REQUIREMENTS OF NEW SYSTEM
A unified web interface capable of displaying 300+ SKUs with real-time text/voice search, backed by an architecture that will not crash under sudden demand spikes.

4.4 FEASIBILITY STUDY
- Economic Feasibility: High. Utilizing open-source tools (Docker, React, Node.js) results in zero software licensing costs.
- Technical Feasibility: High. The technologies are well-documented, widely supported, and fit perfectly within modern DevOps paradigms.
- Operational Feasibility: High. The UI is designed to be highly intuitive with a 1:1 split-screen desktop layout and responsive mobile views.

4.5 NEW SYSTEM ACTIVITY PROCESS
Users arrive via the browser -> Nginx proxies connection to React -> React fetches JSON from Node.js Product Service -> User filters via Search/Voice -> User views product -> User clicks WhatsApp Inquiry.

4.6 FEATURES OF NEW SYSTEM
Modular UI components, Docker-Compose network isolation, dual-image GPO sliders, auto-seeding database scripts.

5.0 SYSTEM DESIGN

5.1 APPLICATION DESIGN
The application follows the MVC (Model-View-Controller) design pattern within the backend services and a Component-Based architecture for the frontend. Services communicate strictly via REST APIs over the internal Docker bridge network.

5.2 INPUT/OUTPUT AND INTERFACE DESIGN
The interface utilizes a "Luxe" theme (Gold and Deep Charcoal). Product Details exhibit a 1:1 right-split aspect ratio, ensuring fabric scans are never dynamically cropped by CSS rules. Input mechanisms include interactive color swatches and the Web Speech API integration.


6.0 IMPLEMENTATION PLANNING

6.1 IMPLEMENTATION ENVIRONMENT
Local development via Windows Subsystem for Linux (WSL). Database instances are decoupled from host OS via containerization. 

6.2 MODULE SPECIFICATIONS
- Nginx Conf: Configured to map `/api/products(.*)` to `http://product-service:5002` and `/api/ratings(.*)` to `http://ratings-service:5003`. 
- Seeding Script (`reseed_gpo_clean.js`): Automatically purges erratic string names and enforces 1-to-1 file matching for Riva 1 and Riva 2 folders.

6.3 SECURITY FEATURES
Hidden underlying service ports; only port 3000 (Frontend) is exposed to the host machine. 

6.4 CODING STANDARDS
Strict adherence to ES6 JavaScript paradigms. Functional React components with specific React Hooks (`useState`, `useEffect`) manage localized state, while `CartContext` handles global states.

8.0 CONCLUSION AND DISCUSSION

8.1 VIABILITY ANALYSIS
The application proves exceptionally viable for deployment to cloud infrastructures utilizing container orchestration like Kubernetes or AWS ECS, directly correlating with the fundamental project goals.

8.2 PROBLEMS ENCOUNTERED
Primary friction involved Nginx trailing slash mishandling leading to 404 Route Not Found errors across the independent microservices, which required advanced Regex matching inside `nginx.conf` to rectify.

8.3 SUMMARY
Luxe Laces stands as a robust enterprise solution demonstrating high proficiency in Full-Stack MERN development merged with strict DevOps methodologies and container deployment.


9.0 LIMITATION AND FUTURE ENHANCEMENT
Limitations: Currently relies on local static file directories mounted within the container rather than an external CDN like AWS S3. 
Future Enhancements: Integration of real-time inventory decrement logic, WebSockets for live user notifications, and transition to a managed Kubernetes cluster.
